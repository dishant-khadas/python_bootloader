# Python Bootloader Error Codes

This document provides a comprehensive list of all error codes generated by the Python Bootloader Application during its operation lifecycle. The errors are categorized into four distinct phases to help support engineers and developers quickly identify the failure context.

---

## 1. Login & Authentication Phase (`L-XX`)
*Errors occurring during the initial service engineer login process.*

| Error Code | Error Name                  | Description |
| :--------- | :-------------------------- | :---------- |
| **L-10**   | Login Network Error         | The device could not connect to the remote server to verify credentials. This may be due to DNS failure, the server being unreachable, or lack of internet connectivity. |
| **L-11**   | Invalid Credentials         | The user provided an incorrect phone number or password resulting in an HTTP 401/403 response. |
| **L-12**   | Login API Timeout           | The remote server took too long to respond to the login request (exceeded timeout threshold). |
| **L-13**   | Missing Authentication Data | The API returned a success status code, but failed to provide a valid JWT token or Employee data in the response payload. |

---

## 2. Handshake & DU Detection Phase (`H-XX`)
*Errors occurring while the system communicates via serial port to detect the DU (Dispenser Unit) and read its initial 512-byte payload.*

| Error Code | Error Name                  | Description |
| :--------- | :-------------------------- | :---------- |
| **H-14**   | Serial Port Open Error      | The application was unable to open the configured serial port (e.g., `/dev/ttyAMA0`) to communicate with the display hardware. |
| **H-31**   | Serial Read Timeout         | The serial port was opened successfully, but no data was received from the display during the handshake timeout window. |
| **H-39**   | No DU Assigned              | The server reports that there is no Dispenser Unit assigned to the currently logged-in Service Engineer. |
| **H-40**   | DU_Update API Error         | Failed to fetch the available firmware update list from the server (due to a network drop or HTTP error). |
| **H-42**   | Invalid Frame Formatting    | The 512-byte payload received does not have the expected SOP (Start of Packet) or EOP (End of Packet) markers. |
| **H-43**   | CRC Validation Failed       | Data corruption occurred in transit. The calculated CRC16 of the payload does not match the received CRC bytes. |
| **H-52**   | Frame Decryption Failed     | The system failed to decrypt the 512-byte payload, usually indicating an encryption key mismatch or corrupted cipher text. |
| **H-58**   | Invalid Serial Number       | The parsed DU Number or Display Number violates system format rules (e.g., wrong length, or DU not starting with 99 / Display not starting with 12). |
| **H-59**   | Invalid Hardware Type       | Byte 427 of the handshake payload contains an unrecognized hardware identifier. |

---

## 3. Firmware Download & Prep Phase (`D-XX`)
*Errors occurring while downloading the selected firmware update, validating its integrity, and decrypting the payload before flashing.*

| Error Code | Error Name                  | Description |
| :--------- | :-------------------------- | :---------- |
| **D-20**   | No Firmware Available       | The DU API returned an empty list of firmware files for the current hardware. |
| **D-21**   | Download API Failed         | The system failed to download the `.bin` firmware file from the server (HTTP non-200 response). |
| **D-22**   | Missing Headers             | The server response is missing critical HTTP headers, such as the encrypted Hash or the KMS Encrypted Key header. |
| **D-23**   | Encrypted Hash Mismatch     | The calculated SHA-256 hash of the downloaded encrypted file does not match the `X-Encrypted-File-Hash` provided by the server. |
| **D-24**   | Original Hash Mismatch      | The calculated SHA-256 hash of the *decrypted* file does not match the `X-Original-File-Hash` provided by the server, indicating data corruption or incorrect decryption. |
| **D-25**   | KMS Decryption Error        | AWS Key Management Service (KMS) failed to decrypt the firmware's data key. |
| **D-26**   | AES File Decryption Error   | The system failed to decrypt the firmware file payload using the decrypted KMS data key. |
| **D-28**   | Serial Write Error          | The system failed to successfully send the final 64-byte or 512-byte hash packet to the display hardware over the serial port. |
| **D-29**   | Hash Packet Timeout         | The system sent the Hash Packet successfully, but no response or acknowledgment was received back from the display. |

---

## 4. Firmware Programming Phase (`P-XX`)
*Errors occurring while the `btl_host.py` utility physically flashes the binary onto the PIC32 hardware.*

| Error Code | Error Name                  | Description |
| :--------- | :-------------------------- | :---------- |
| **P-15**   | Firmware Update Failed      | The underlying `btl_host.py` process exited with a non-zero exit code, threw an internal error, or lost communication with the PIC32 bootloader during the flashing cycle. |
